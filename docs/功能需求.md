# OPC 第一版功能需求

版本：2026-10-11。这份文档只规定第一版要做什么、做成什么样。技术方案仍以 `README.md` 的「技术方案」为准。页面长什么样以 `preview/board.html` 为准，行为以本文为准。两边冲突时，先改本文，再改页面。

第一版是给 Boheng 一个人用的本机看板。打开它就能看见本周重点、正在做的事、等你拍板的事。任务、决定和本周重点记在 MySQL 里，刷新后还在。

## 使用者

只有你。没有注册、没有多人或多公司。服务放在本机时，打开页面的人就是你。

你用它做三件事：把一句话收进来，看一条任务做到哪了，批准或退回。策划、工程、研究和运营仍按 `roles/` 里的手册在仓库里干活，第一版页面不代替他们执行。

## 第一版要能走完的一天

1. 打开看板，看见本周唯一重点。
2. 把一句新需求收进收件。
3. 点开一条待批准的任务，看验收和产出。
4. 写下结论后批准，或写下原因后退回。
5. 刷新页面，刚才的任务状态和决定还在。
6. 进行中已经有 2 条时，不能再把别的任务提成现在就做。

## 页面

一屏，深色。从左到右四块，对应 `preview/board.html`：

| 区域 | 显示 | 你能做的操作 |
| --- | --- | --- |
| 窄导航 | OPC 标志，以及看板、角色、公司三个入口 | 进入对应模块。当前模块高亮 |
| 左栏 | 本周唯一重点、起止日期、待批准数量、阻塞数量、最近一条决定 | 修改并保存本周重点；点数量，中栏滚到对应分组 |
| 中栏 | 标题「现在」。下面按进行中、待批准、阻塞、收件分组，只列 `priority = now` 的任务。底部是收件框 | 点一条任务；提交一句话 |
| 右栏 | 选中任务的编号、角色、状态、目标、验收、产出路径、记录 | 待批准时可写结论、勾选记入决策、批准或退回 |

地址栏带 `?task=t-001`。刷新后右栏仍是这一条。没有选中任务时，右栏写「选一条任务」。

中栏下方另有一块「接下来」，只列 `priority = next` 的任务。每条有「提为现在」。`later` 不出现在这一屏。

空状态：

- 没有本周重点时，左栏重点区是空的，中栏提示先写下本周重点。
- 某个分组没有任务时，该组写「没有进行中的任务」这类句子。
- 没有任务时，收件框仍是中栏底部的主操作。

完成的任务离开中栏。它的结论若已记入决策，出现在左栏「最近决定」。

## 功能

每条都要能在浏览器里单独验收。

### F1 看见本周重点

左栏显示 `goals` 里的本周唯一重点和起止日期。没有重点时显示空，并提示你填写。

### F2 修改本周重点

你在左栏改文字并保存。系统只更新本周重点这一项，本季目标和其他章节保留。保存后，当前 `priority = now` 且状态不是 `done` 的任务改为 `blocked`，`blockReason` 为「目标已变，需重新规划」。

### F3 按状态看现在的任务

中栏四个分组只包含 `priority = now` 的任务。分组顺序是进行中、待批准、阻塞、收件。每条显示标题、编号、角色。选中的一条有明确的选中样式。

### F4 打开任务

点中栏或「接下来」里的一条，右栏换成它的内容，地址变为 `?task=` 加它的编号。右栏列出目标、验收、产出路径、记录。产出路径是仓库相对路径，用等宽字显示。

### F5 收件

在中栏底部写下非空的一句话并提交。系统新建任务：

- `brief` 是原话，不改写
- `title` 先取原话，最长显示约一行
- `status` 为 `inbox`
- `role` 是 `roles/` 里标了「收件默认: 是」的那份手册。没有标记时，用文件名排序后的第一份
- `goal` 为「待策划收成可检查的验收。」
- `acceptance` 先有一条「策划补上可检查的验收」
- `needsApproval` 为真
- 若当前没有 `doing` 任务，`priority` 为 `now`，并出现在中栏收件组；否则 `priority` 为 `next`，出现在「接下来」
- 编号为现有最大编号加一，格式 `t-` 加三位数字，不复用

提交后输入框清空，右栏打开这条新任务。

### F6 批准

只有 `review` 可以批准。结论不能为空。你可勾选「记入决策」，默认勾选。

批准后：

- 状态变为 `done`
- `decision` 写入你的结论
- `notes` 追加一条，以时间、`你`、结论开头
- 勾选记入决策时，新增一条决定，含日期、结论、任务编号
- 这条任务从中栏消失
- 左栏最近决定换成这条结论
- 批准和退回按钮变为不可用

`artifacts` 为空，且这条任务的产出不是「写一条决定」时，批准被拒绝，任务保持 `review`。

### F7 退回

只有 `review` 可以退回。退回原因不能为空。

退回后状态变为 `doing`，`notes` 追加退回原因，任务出现在进行中。若进行中因此会超过 2 条，退回被拒绝，页面说明进行中已满。

### F8 提为现在

「接下来」里的任务可以提为 `now`。若它会进入 `doing`，或你是把它提上来准备开工，而当前 `doing` 已有 2 条，操作被拒绝，页面写出原因。提为 `inbox` 或 `blocked` 的 `now` 不受这 2 条限制。

### F9 刷新后还在

收件、批准、退回、提为现在、修改本周重点，刷新页面后与刷新前一致。这些数据来自 MySQL。

### F10 文件副本

上述写入在数据库事务成功后，刷新对应的 `tasks/t-xxx.json`。记入决策时刷新 `decisions.md` 的「已生效的条目」。修改本周重点时只替换 `goals.md` 的「本周唯一重点」一节。

导出失败时，页面说明数据库已写入、文件副本尚未刷新。下一次成功写入会再次导出。人和代理以数据库为准。

### F11 导入已有任务

数据库里还没有任务、仓库里已有 `tasks/t-*.json` 时，启动导入一次。现有的 `t-001` 导入后仍是待批准，右栏能打开它。

## 状态规则

```text
inbox ──补齐验收与角色──► doing ──产出落地──► review ──你批准──► done
  ▲                        │                   │
  │                        ▼                   │ 你退回
  └────────你补充材料────── blocked ◄──────────┘
```

| 状态 | 页面上的名字 | 第一版里谁来改变它 |
| --- | --- | --- |
| `inbox` | 收件 | 收件时新建。补齐验收后进入进行中，这一步第一版由你或代理改数据，页面不提供「开始做」 |
| `doing` | 进行中 | 退回可以回到这里。进入待批准由代理把产出写上之后完成，页面不提供按钮 |
| `review` | 待批准 | 你批准或退回 |
| `blocked` | 阻塞 | 本周重点一改，未完成的现在任务进入这里。你补齐材料后如何离开阻塞，第一版不在页面上提供按钮 |
| `done` | 完成 | 只由批准进入。之后的变化另开新任务 |

同时处于进行中、且优先级为现在的任务最多 2 条。超过时接口拒绝，页面显示原因。

角色不能把任务标成完成。页面上的批准是你的动作。

## 第一版不包含

这些留到后面的版本，第一版页面不出现对应按钮：

- 调用模型，或在页面里让角色自动执行
- 推远程、发布、对外发送、花钱
- 日历、统计图、多项目
- 登录和多用户
- 在页面里编辑身份、用户文档或角色手册
- 在页面里把阻塞任务改回收件或进行中

侧栏「员工」里可以添加和移除员工。点进一个人是对话：你是老板，消息记在数据库里。提示词和技能在这个人的「背后」页面，不铺在对话里。模型未接入时，员工会回复还没有接上，不会向外发出请求。调用位置仍是 `lib/employees/model.ts`。

## 数据

任务字段就这些，第一版不增加列：`id`、`title`、`brief`、`goal`、`acceptance`、`role`、`status`、`priority`、`artifacts`、`notes`、`needsApproval`、`blockReason`、`decision`、`createdAt`、`updatedAt`。

本周重点、本季目标、本周起止、这周范围之外放在 `goals` 的一行里。已生效决定放在 `decisions`，只新增，不改旧行。

身份、用户笔记、角色手册、研究笔记、运营草稿仍是文件，第一版看板只读角色名，不改这些文件。

## 和页面示意的差别

`preview/board.html` 用来看布局和深色样式。它还没有下面这些，做到第一版时要补上：

- 刷新后数据仍在
- 「接下来」和「提为现在」
- 左栏可以保存本周重点，并让未完成的现在任务变为阻塞
- 退回必须填写原因
- 批准时产出为空会被拒绝
- 待批准数量、阻塞数量可以滚到对应分组

示意里的收件、点选、批准已在窗口里走过。那些操作刷新后会消失，直到 F9 做完。
