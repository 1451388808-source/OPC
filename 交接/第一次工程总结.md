# OPC 第一次工程总结

日期：2026-10-11 至 2026-10-12。给下一次接手的人用。产品规划仍以 `README.md` 为准，功能范围以 `docs/功能需求.md` 为准。这份文件只记录已经做出的东西、怎么跑起来、以及还没做完的地方。

## 这是什么

OPC 是 Boheng 一个人用的公司操作系统。他是老板：定目标、做取舍、批准结果。员工是可添加、可移除的小智能体。每个员工有自己的提示词和技能，模型以后再接。现在模型没有接上，对话会停在「还没有接入模型」。

系统按四期做：

| 期 | 内容 | 进度 |
| --- | --- | --- |
| 第一期 | 公司记忆、角色手册、任务 `t-001` | 已完成 |
| 第二期 | 本机看板、MySQL、员工名单和对话 | 主路径可用，还没收口 |
| 第三期 | 运行壳，让员工按手册调用模型，结果停在待批准 | 未开始。模型接口已留在 `lib/employees/model.ts` |
| 第四期 | 批准之后才允许推远程、复制对外草稿 | 未开始 |

Docker 留给别人部署，这一期先不做。本机直接跑 Node 和已经装好的 MySQL。

## 怎么打开

1. MySQL 服务名是 `MySQL84`，要处于运行状态。
2. 项目根目录要有 `.env.local`，内容是：

```text
DATABASE_URL=mysql://opc:<本机密码>@127.0.0.1:3306/opc
```

这个文件不进版本库。库名 `opc`，用户 `opc`，密码 `opc-local`。没有改过本机 root 密码。

3. 在项目根目录执行 `npm run dev`，打开 `http://127.0.0.1:3000`。
4. 状态机测试：`npm test`。

启动时会执行 `db/migrations/` 里的 SQL，并在任务表为空时导入 `tasks/t-*.json`。现有 `t-001` 已导入，状态是待批准。不要为了试功能去批准它，那会写成一条正式决定。

## 页面

左侧窄栏是模块入口：

- **看板**：本周重点、任务分组、收件、批准、退回、提为现在。
- **员工**：添加、移除、对话。点进去左边名单还在，中间有 `‹` / `›` 可收起。右上角「背后」才是提示词、技能和模型。
- **公司**：身份、目标、决策、用户四份文件的阅读页。

深色界面参考了 Codex 桌面端。标志是蓝底圆角方标，白色折角加一个点，不是 OpenAI 的原标志。

## 员工怎么配

一个员工是 `roles/` 里的一份手册。

- 文件名是 id，例如 `planner.md`。
- 一级标题是看板上的名字。
- `收件默认: 是` 表示新收件交给他。现在只有策划。
- `## 提示词`、`## 技能`、`## 模型` 三节给智能体用。
- 技能是 `skills/` 里的文件，手册里一行一个 id。
- 模型两行先空着：`provider:` 和 `model:`。

添加员工会新建 `roles/e-001.md` 这种文件。移除时，如果还有任务的 `role` 指向他，会拒绝删除。

对话存在 MySQL 的 `messages` 表。老板的话会记下来。员工回复目前只会说明模型没接上。以后在 `lib/employees/model.ts` 里用 `registerModel(provider, adapter)` 接上真正的调用。`runEmployee` 在 provider 为空或尚未注册时抛出 `ModelNotConnectedError`。

现有四名员工和技能：

| 员工 | id | 技能 |
| --- | --- | --- |
| 策划 | planner | task-shaping，收成任务 |
| 工程 | engineer | implement-and-verify，实现并对照验收 |
| 研究 | researcher | sourced-notes，带来源的笔记 |
| 运营 | operator | draft-not-send，草稿不发送 |

## 数据放哪

MySQL 是任务、决定、本周重点、对话的正本。

| 表 | 内容 |
| --- | --- |
| `tasks` | 任务。`role` 已是普通文本，不再是固定枚举 |
| `decisions` | 批准时勾选记入的决定，只追加 |
| `goals` | 本季目标、本周重点、起止日期 |
| `messages` | 老板和员工的对话 |
| `counters` | 任务编号 |

写入成功后，再导出 `tasks/t-xxx.json`，并按需要刷新 `decisions.md` 和 `goals.md` 的「本周唯一重点」第一段。导出失败时页面会说明数据库已写入、文件副本尚未刷新。两边不一致时以 MySQL 为准。

身份、用户笔记、角色手册、技能仍是文件。公司页只读这些文件，不在页面里改。

## 已经在浏览器里走过的

- 看板打开后能看见本周重点和 `t-001`
- 收件会新建任务，刷新后还在，并写出 JSON
- 待批准任务可以退回，原因进入记录，状态变成进行中
- 空库导入 `t-001`
- 添加员工、进入对话、收到「还没有接入模型」、打开背后页
- 员工名单在对话时保留，并能收起、展开
- 移除按钮是名字右边的小垃圾桶

验证用的临时员工和临时任务已经删掉。库里应只剩 `t-001`。

## 第二期还没在页面上点过的

这些代码在，收口前需要再走一遍：

- 批准一条有产出的待批准任务，并勾选记入决策，确认 `decisions.md` 被刷新
- 没有产出时批准会被拒绝
- 「接下来」里的任务提为现在
- 保存本周重点后，未完成的当前任务变成阻塞，原因是「目标已变，需重新规划」
- 进行中已经有 2 条时，退回或提为现在会在页面上被拒绝

`preview/board.html` 是更早的静态示意，不是现在的程序。以 `http://127.0.0.1:3000` 为准。

## 接手时不要做的事

- 不要批准 `t-001`，除非 Boheng 明确要记下那条决定。
- 不要把 `.env.local` 提交出去。
- 不要在模型未注册时假装员工已经完成了任务。
- 不要先做 Docker。`docker-compose.yml` 和 `Dockerfile` 先留着。
