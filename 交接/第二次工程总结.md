## 怎么打开

1. MySQL 服务名是 `MySQL84`，要处于运行状态。
2. 项目根目录要有 `.env.local`，不进版本库。现在有两行：

```text
DATABASE_URL=mysql://opc:<本机密码>@127.0.0.1:3306/opc
DEEPSEEK_API_KEY=
```

库名 `opc`，用户 `opc`，密码只保存在本机 `.env.local`。密钥只放在 `DEEPSEEK_API_KEY`，不要写进角色手册或这份文档。`.env.example` 里只有空的变量名。

3. 在项目根目录执行 `npm run dev`，打开 `http://127.0.0.1:3000`。
4. 状态机测试：`npm test`。

改了 `.env.local` 之后要重新执行 `npm run dev`，正在跑的进程不会自己读到新密钥。

启动时会执行 `db/migrations/` 里的 SQL。任务表为空时导入 `tasks/t-*.json`。`t-001` 仍是待批准。不要为了试功能去批准它。

本机库里已经有一家公司 `opc`（`c-001`）和一个项目「做一个小网站」（`p-001`）。对话里有试发的句子。工程、策划、研究在这个项目里。运营还没加进去。

员工还没进项目就发送，会说明先把员工加进去。

## 模型

四名员工手册里都是：

```text
provider: deepseek
model: deepseek-flash
```

`deepseek-flash` 是 DeepSeek-V4.1-Flash。调用在 `lib/employees/deepseek.ts`，思考模式开着。项目对话走流式接口 `POST /api/projects/[id]/messages`，事件是一行一条 `data:`。

两段文字不要混：

| 文字 | 放哪 | 写什么 |
| --- | --- | --- |
| 思考过程 | 对话里这条回复上，可收起 | 模型这一轮的 `reasoning_content`，流式出现 |
| 对这个项目的思考 | 左侧该员工名下，最多两行；表 `project_thinking` | 一两句：项目现在怎样、还缺什么。每次接话按整段对话重写 |

一对一对话仍把思考过程存在 `messages` 正文里，格式是 `---思考---` 和 `---回复---`。

## 数据放哪

MySQL 仍是任务、决定、本周重点、对话的正本。这一轮多了这些表，见 `db/migrations/004_companies.sql`、`005_project_thinking.sql`：

| 表 | 内容 |
| --- | --- |
| `companies` | 公司。编号 `c-001` |
| `projects` | 项目，属于一家公司。编号 `p-001` |
| `project_members` | 项目里的员工 |
| `project_thinking` | 某员工对某个项目的短判断 |
| `project_messages` | 项目共用对话。员工回复里可以带思考过程 |

身份、目标、决策、用户、角色手册、技能仍是文件。任务 JSON 副本的规则没变。
