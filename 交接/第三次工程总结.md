## 用户流程

### 项目群聊派工

1. 打开公司项目。
2. 在群聊输入区选择一名员工。
3. 写执行要求，按 Enter 或点击“执行任务”。
4. 群聊持续显示思考、工具调用、工具结果、摘要和修改文件。
5. 点击“查看文件并审批”，查看 diff 后批准或退回。

“发送消息”只讨论，不获得文件工具。

工具执行采用流式输出：思考和最终回复会逐段进入聊天区，连续片段合并显示，工具调用穿插在过程里。刷新后用事件表重建同一流程。

### 看板任务派工

1. 打开 `priority = now` 且状态为 `inbox/doing` 的任务。
2. 选择项目和该项目内员工，点击“交给员工”。
3. 任务变为 `doing`，后台执行。
4. 有真实文件产出后，执行和任务一起进入 `review`。
5. 在任务详情批准时，系统应用文件、批准执行并把任务改为 `done`。

## 文件边界

正式项目目录：

```text
workspaces/<companyId>/<projectId>/
```

执行暂存目录：

```text
.opc/runs/<runId>/
```

只支持 UTF-8 文本工具。文本型 HTML `.doc` 可以由 Word/WPS 打开；`.docx/.xlsx/.pptx/.pdf` 等需要二进制编码的格式被拒绝。

路径守卫拒绝绝对路径、`..`、盘符、UNC、反斜杠逃逸、符号链接、Windows 设备名和内部目录。单文件、单次文件数、总大小、模型轮数、工具次数、重复调用和执行时间均有限制。

## 数据

迁移 `db/migrations/006_project_runs.sql` 增加：

- `project_runs`
- `project_run_events`
- `project_run_files`

执行状态：

```text
queued → running → review → applying → approved
                    ├──────────────→ returned
                    └──────────────→ failed
```

终态执行的 `.opc` 暂存目录默认保留 30 天，可用 `PROJECT_RUN_RETENTION_DAYS` 调整。`review/applying` 永不自动清理。
